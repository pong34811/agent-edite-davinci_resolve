# Game and channel identification: evidence contract

This is a review procedure, not an automated classifier or proof of a live capability.
Never modify source footage or Resolve state for identification.

1. Establish the project and channel the user specified; consult only that channel's indexed profile. A profile, folder or filename is a clue, not proof of the footage's game or ownership. If the channel is unspecified or the evidence conflicts, do not borrow another profile.
2. Inventory using available read-only MCP actions: record project ID, timeline ID, media pool item ID, source path and ranges. Probe actual tool availability and schema; if Resolve or media is offline, unavailable, or inaccessible, record what was not inspected and use unknown. Do not launch Resolve or alter state.
3. With permission and within the approved local analysis scope, inspect samples near the beginning, middle and end, plus more around scene changes or suspected game changes. Record exact timestamps and observed HUD, in-frame game title, visual features, audio or spoken clues. Filename, ASR, OCR and sampled images can be wrong; samples and ASR do not prove the content of an entire clip. If no vision, audio or inspection is available, say so and leave the identity unknown.
4. Keep game identity and channel identity as separate evidence and decisions. An avatar or game alone does not establish which channel owns footage. Multiple games may occur: preserve a multi-game timeline as separate observed ranges; do not invent exact transition boundaries from sparse samples. Mark gaps and uninspected ranges unknown.
5. For each range produce `{start, end, game, channel, game_status, game_evidence, channel_status, channel_evidence}` with project/timeline ID, media ID/path, and explicit source or timeline time base (including frame rate when using frames). State how source and timeline ranges map if both are reported. Evidence includes observed timestamps, modality, what was actually observed, and limitations. Use separate statuses for game and channel when their evidence differs: **confirmed** only when adequately corroborated or explicitly confirmed by the user, **candidate** for a plausible but unverified identification, **unknown** for insufficient evidence, and **conflict** for contradictory evidence. Do not fabricate numerical confidence. Ask the user to resolve conflicts or confirm candidates; do not guess.

## Permission and write safety

Do not send footage, audio, transcripts or private information to an external provider without explicit permission covering the material, recipient and purpose. Local sampling artifacts require an approved separate analysis location, never source paths; respect any stricter no-write instruction. Inventory and analysis do not authorize edits, renders, uploads, markers or metadata changes.

The `analyze_media` prompt can write project metadata and markers by default. Prefer a verified read-only action; before using it, inspect the actual schema and explicitly disable all writes, including `publish_metadata=false` and `timed_markers=no`. Disable unapproved visual and transcription operations with `include_visuals=false` and `include_transcription=false`. These options alone are not proof that every other output or side effect is disabled: verify the action's actual defaults and output paths first. If a no-write mode cannot be established, do not run it. Never infer live support from this document.
