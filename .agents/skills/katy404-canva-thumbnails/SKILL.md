# KATY404 Canva Thumbnails

สร้างปกจากหัวข้อ สคริปต์ หรือภาพที่ผู้ใช้ให้ โดยรักษาภาษาภาพของ KATY404 และส่งลิงก์ Canva ที่แก้ไขต่อได้ ตอบผู้ใช้เป็นภาษาไทย เว้นแต่ผู้ใช้ขอภาษาอื่น

## เริ่มจากข้อมูลที่มี

- อ่านบริบทเดิมก่อนถามซ้ำ: หัวข้อ/เหตุการณ์หลัก, ประเภทปก, ภาพเกม, อวาตาร์, ข้อความที่ต้องใช้ และจำนวนแบบ
- ถ้ามีเพียงคำว่า “ทำปกให้หน่อย” ให้ถามหัวข้อหรือเหตุการณ์หลักหนึ่งคำถาม ถ้ามีหัวข้อพอแล้ว ให้เดินหน้าจัดทำ brief
- ใช้ไฟล์ ข้อความ และหน้าต้นแบบที่ผู้ใช้ระบุเป็นหลัก ไม่เปลี่ยนเป็นเกมอื่น อวาตาร์อื่น หรือเครื่องมืออื่นเอง
- ค่าเริ่มต้นเมื่อไม่ได้ระบุ: ปกคลิปแนวนอน 1920×1080 จำนวน 1 แบบ และบอกสมมติฐานสั้น ๆ; Shorts ใช้ 1080×1920; LIVE ใช้ 1920×1080 ขนาดที่ผู้ใช้ระบุมีลำดับสูงกว่า
- ถ้าผู้ใช้ขอหลายสัดส่วน ให้ทำเป็นงานแยกตามสัดส่วน ไม่ยืดหรือบีบภาพเดิม
- สำหรับปก Shorts แนวตั้ง ให้จัดข้อความ hook และข้อความรองกึ่งกลางตามแนวนอนและเรียงซ้อนให้อ่านชัด วางโมเดล/อวาตาร์ไว้กึ่งกลางแนวนอนบริเวณครึ่งล่าง และตรวจว่าไม่ถูกตัดหรือทับข้อความ เว้นแต่ผู้ใช้กำหนดตำแหน่งอื่น
- ถ้าขาดภาพเหตุการณ์จริง ให้ขอภาพ/เวลาในคลิป หรือใช้ฉากกลางที่เหมาะกับเรื่องพร้อมบอกว่าเป็นภาพประกอบ อย่าเอาเหตุการณ์ของคลิปเก่ามาอ้างว่าเป็นเหตุการณ์ใหม่
- หากผู้ใช้ขอเพียงไอเดีย ข้อความ หรือ prompt ให้ส่งเท่านั้น ไม่สร้างงาน Canva โดยอัตโนมัติ
- ถ้าผู้ใช้ขอ JPG/PNG/ZIP แต่ไม่ได้ขอ Canva ให้ทำและตรวจไฟล์ภาพตาม brief โดยไม่สร้างหรือแก้ดีไซน์ Canva เพิ่ม เมื่อผู้ใช้เปลี่ยนใจระหว่างงาน ให้หยุดการเรียก Canva และส่งไฟล์ภาพที่ทำเสร็จแล้ว

สรุป brief ให้สั้น: `ประเภท • ขนาด • เหตุการณ์ • hook • ภาพหลัก • ต้นแบบ • จำนวน` งานที่ชัดเจนไม่ต้องขออนุมัติ brief ซ้ำก่อนลงมือ

## ตรวจ Timeline และหลักฐานจากวิดีโอ

เมื่อผู้ใช้ให้โปรเจกต์ตัดต่อ, วิดีโอ, subtitle หรือหลาย Timeline ให้ตรวจโปรเจกต์ปัจจุบันก่อนใช้ไฟล์สรุปเดิม:

- นับและบันทึกชื่อ Timeline, ขนาด, fps, ช่วงเวลา, source clip และ subtitle track ของทุก Timeline ที่อยู่ในขอบเขตงาน ถ้ามีแนวนอนและ Shorts ให้จับคู่จากข้อมูลจริง ไม่เดาจากลำดับไฟล์
- เลือก hook จากคำพูดหรือข้อความบน Timeline ที่มีหลักฐานจริง แล้วเลือกเฟรมจากช่วงเวลาเดียวกัน เก็บ `timeline name • hook • secondary • source path • source time/frame • model` เป็น manifest เพื่อย้อนตรวจได้
- ถ้าชื่อ Timeline กับบทพูดไม่ตรงกัน ให้ยึดข้อความ/เหตุการณ์ที่เห็นใน subtitle และเฟรมจริงเพื่อไม่เพิ่มคำกล่าวอ้าง แล้วระบุความคลาดเคลื่อนสั้น ๆ ใน manifest หรือรายงานส่งมอบ
- อย่าใช้เฟรม, subtitle, manifest หรือ JPG จากโปรเจกต์เก่าเพียงเพราะอยู่ในโฟลเดอร์เดียวกัน ตรวจ project identity และ source path ก่อนนำมาใช้ทุกครั้ง
- ถ้าไม่มี subtitle ที่เชื่อถือได้ ให้ขอเวลาในคลิปหรือภาพเหตุการณ์ก่อนสรุป hook; อย่าแต่งเหตุการณ์จากชื่อไฟล์อย่างเดียว

เมื่อมี Timeline จำนวนมาก ให้สร้างรายการผลลัพธ์หนึ่งรายการต่อชื่อ Timeline จริง ใช้ชื่อเดิมเป็นชื่อไฟล์ และเปลี่ยนเฉพาะอักขระที่ระบบไฟล์ใช้ไม่ได้ การทำปกคู่แนวนอน/แนวตั้งต้องจัดวางใหม่ตามสัดส่วน ไม่ครอปแนวนอนแล้วอ้างว่าเป็น Shorts ที่ตรวจแล้ว

## เลือกต้นแบบจากภาพจริง

อ่าน [style-guide.md](references/style-guide.md) และเปิดภาพ contact sheet ของประเภทที่เกี่ยวข้องก่อนออกแบบ ดู [source-manifest.json](references/source-manifest.json) สำหรับ URL เต็มและ page ID

1. ถ้าผู้ใช้เลือกหน้า ให้เริ่มจากหน้านั้น มิฉะนั้นเลือกหน้าที่สัดส่วน จำนวนข้อความ ตำแหน่งตัวละคร และอารมณ์รองรับเรื่องใหม่
2. เปิดข้อมูลและ preview ปัจจุบันผ่าน Canva ก่อนคัดลอก หมายเลขหน้าอาจเลื่อนจาก snapshot ที่บันทึกไว้ ตรวจ page ID และภาพประกอบกัน
3. คัดลอกเฉพาะหน้าที่ใช้ ไม่คัดลอกทั้งคอลเลกชันซึ่งมีหลายสิบถึงร้อยหน้า
4. แก้สำเนาใหม่เป็นค่าเริ่มต้น เว้นแต่ผู้ใช้เจาะจงให้แก้งานเดิม
5. ตรวจเลเยอร์หลังคัดลอกก่อนรับปากว่าทุกส่วนแก้ไขได้ ปกชิบิบางหน้าอาจประกอบด้วยภาพแบนที่มีข้อความฝังอยู่

## เปลี่ยนเรื่องให้เป็นปก

- เลือกหนึ่งเหตุการณ์หรือหนึ่งอารมณ์ที่มีหลักฐานในคลิป ใช้ hook ไทยสั้นที่อ่านจบเร็ว เช่น “อุบัติเหตุ”, “คุยกับใครอยู่”, “ติดที่เดียวกัน” ไม่ใช้ข้อความตัวอย่างกับคลิปที่ไม่เกี่ยวข้อง
- คิดทางเลือกข้อความ 2–3 แบบภายใน แล้วใช้แบบที่ชัดที่สุด ถ้าผู้ใช้ขอให้เลือกก่อน ค่อยแสดงตัวเลือกและรอคำตอบ
- ตั้งต้นที่ 1–2 บรรทัด ใช้คำเน้นหนึ่งจุด เมื่อข้อความยาวให้ย่อก่อนลดขนาดจนอ่านยาก ถ้าผู้ใช้ล็อกข้อความไว้ ห้ามย่อโดยพลการ ให้เปลี่ยนการจัดวางแทน
- **วิเคราะห์ลำดับข้อความ:** ก่อนจัดวาง ให้ระบุ hook หลักที่สื่อเหตุการณ์หรืออารมณ์เด่นที่สุด แล้วแยกจากข้อความรองที่ให้บริบทหรือผลลัพธ์ ตัวอย่าง “ช่วยด้วย” เป็น hook หลัก ส่วน “ติดที่เดียวกัน” เป็นข้อความรอง วาง hook ให้ใหญ่หรือเด่นกว่า และให้ข้อความรองเล็กลง อย่าเน้นทุกวลีเท่ากัน
- **สีและฟอนต์สำหรับปก KATY404:** ใช้ Mitr Bold และเส้นขอบสีดำกับข้อความ overlay; ทำ hook หลักที่มีขนาดใหญ่เป็นสีแดงตามตัวอย่าง และใช้สีขาวกับบรรทัดรอง ถ้าต้นแบบมีหลายคำสีแดง ให้คงสีแดงไว้เฉพาะ hook หลักและเปลี่ยนข้อความรองเป็นสีขาว อย่าทำทุกข้อความเป็นสีแดง สีแดงในกรอบ ลูกศร วงกลม หรือกราฟิกยังใช้ได้ตามความเหมาะสม
- ไม่เพิ่มคำกล่าวอ้าง ยอดผู้ติดตาม เป้าหมาย ตัวเลขตอน ชื่อเพื่อน หรือ LIVE ที่ไม่มีข้อมูลรองรับ
- รักษาคำสะกด ชื่อบุคคล และศัพท์เกมตามข้อมูลที่ให้ ตรวจสระ/วรรณยุกต์ไทยและตัดบรรทัดตามวลี
- ใช้อวาตาร์ต้นฉบับหรือ asset ที่ผู้ใช้ให้ รักษาทรงผม สีตา เครื่องแต่งกาย และตัวตน อย่าสร้างตัวละครหน้าตาคล้ายมาแทน หากต้องการสีหน้าใหม่ให้หาหน้า/asset เดิมที่เหมาะก่อน
- ภาพเกมเป็นบริบท ใบหน้าหรือจุดเกิดเหตุเป็นภาพหลัก และข้อความสื่อ hook; เครื่องหมายตกใจ วงกลม ลูกศร และภาพเพื่อนใช้เมื่อช่วยเข้าใจเหตุการณ์
- ถ้า PNG โมเดลมีพื้นที่โปร่งใสรอบตัว ให้ตรวจ alpha bounding box และจัดกึ่งกลางจากพื้นที่ที่มองเห็น ไม่ใช่จากผืน PNG ทั้งใบ รักษา alpha ระหว่าง compositing และอย่าแปลงเป็น RGB ก่อนวาง
- เลือกสีหน้า/ท่าทางจาก asset ที่มีจริงและหลักฐานในคลิปเท่านั้น ถ้าไม่มี pose ที่ตรง ให้ใช้ pose กลางหรือแจ้งข้อจำกัด ห้ามเรียก pose ว่าตกใจ/เศร้า/โมโหเกินกว่าภาพจริงสื่อ

## สร้างใน Canva

ทำตาม [canva-workflow.md](references/canva-workflow.md) โดยตรวจ schema ของเครื่องมือที่มีจริงในรอบนั้น

เส้นทางหลักคือ **อ่านหน้า → copy เฉพาะหน้า → ตรวจเลเยอร์ → แก้ข้อความ/ภาพ → ตรวจ preview → บันทึกตามเงื่อนไขเครื่องมือ → ส่ง edit URL**

รักษาฟอนต์ เส้นขอบ เงา และลำดับซ้อนที่ติดมากับต้นแบบ เครื่องมือแก้ไขที่ตรวจเมื่อสร้าง skill นี้ไม่มีคำสั่งเพิ่มกล่องข้อความ เปลี่ยน font family หรือสร้าง stroke/shadow ใหม่ ถ้าต้นแบบรองรับไม่ได้ ให้เลือกหน้าที่เหมาะกว่า หรือใช้ Canva UI/เครื่องมือที่รองรับจริง อย่าประดิษฐ์ API ขึ้นเอง

เมื่อ Canva ใช้ไม่ได้ ยังจัดทำข้อความและผังปกได้ แต่ระบุว่าเป็น brief และบอกสิ่งที่ต้องใช้ต่อ ห้ามอ้างว่าสร้างหรือบันทึกงานแล้ว

ถ้าผู้ใช้ขอไฟล์ภาพเป็นหลัก ให้ใช้ renderer ที่ตรวจสอบได้เพื่อทำ JPG/PNG ตามสัดส่วนและสไตล์เดียวกันได้ โดยต้องบอกตามจริงว่าส่วนข้อความ/กราฟิกเป็นภาพแบนและไม่มีลิงก์ Canva หากไม่ได้สร้าง Canva

ก่อนทำ JPG เอง อ่าน [jpg-render-notes.md](references/jpg-render-notes.md): การอ่าน Text+ จาก .drp โดยไม่เปิด Fusion ใน Resolve, การวางข้อความไทย (RAQM, ซ้อนบรรทัดตาม ink, แยกสระ/วรรณยุกต์ที่ติดหาง ป ฝ ฟ และหัว ไ ใ โ), การเบลอสไลด์พื้นหลัง และการครอป/ขอบของโมเดล

## ตรวจงานก่อนส่ง

- **เรื่องและตัวตน:** ภาพ/ข้อความตรงกับคลิป อวาตาร์ถูกตัว ไม่มีชื่อ ตัวเลข โลโก้ หรือคำจากต้นแบบที่ไม่เกี่ยวข้องหลงเหลือ รวมถึงข้อความฝังในภาพ
- **อ่านง่าย:** ดูทั้งขนาดเต็มและย่อเทียบประมาณ 320×180 สำหรับแนวนอน หรือ 180×320 สำหรับแนวตั้ง ถ้าจัดแสดงขนาดนั้นไม่ได้ ให้รายงานขอบเขตที่ตรวจจริง
- **ไทย:** สระและวรรณยุกต์ไม่ถูกตัด ไม่ซ้อนจนอ่านผิด เส้นขอบดำไม่อุดช่องในตัวอักษร ซูมดูคำที่มี ป ฝ ฟ หรือวรรณยุกต์หน้า ไ ใ โ ว่ามีขอบดำคั่นจริง
- **สีข้อความ:** ตรวจว่า hook หลักตัวใหญ่เป็นสีแดง Mitr Bold ขอบดำ และข้อความรองเป็นสีขาว Mitr Bold ขอบดำ สีแดงในภาพเกมที่เป็นส่วนหนึ่งของ footage ไม่ถือเป็นข้อความ overlay
- **ลำดับข้อความ:** ตรวจว่า hook หลักสื่อจุดขาย/เหตุการณ์ชัดและมีขนาดเด่นกว่าข้อความรอง โดยไม่ทำให้คำกล่าวเกินหลักฐานในคลิป
- **ภาพหลัก:** ตา ปาก ท่าทาง และเหตุการณ์สำคัญไม่โดนข้อความบัง ฉากไม่แย่งสายตา ไม่มีกรอบภาพแปลกหรือภาพที่ยังวางทับแบบร่าง
- **สัดส่วน:** ขนาดตรง brief ไม่บีบภาพ ปกแนวตั้งจัดข้อความใหม่ตามพื้นที่จริง และตรวจ crop ของแพลตฟอร์มเมื่อผู้ใช้ระบุ
- **แก้ไขต่อได้:** ตรวจว่าข้อความหลักเป็น text element ถ้าส่วนใดอยู่ใน bitmap ให้แจ้งตามจริง แก้ให้เป็น native text หากเป็นข้อกำหนดและมีเครื่องมือรองรับ
- **สถานะ:** ตรวจผลการบันทึกจริง ไม่เรียก draft ที่ยังไม่ commit ว่างานเสร็จ
- **ไฟล์ส่งออก:** เปิด/ถอดรหัส JPG หรือ PNG ทุกใบ ตรวจ dimensions ให้ตรง brief และตรวจชื่อไฟล์เทียบกับ Timeline manifest
- **แพ็กเกจ:** เมื่อส่งหลายไฟล์ ให้ตรวจจำนวนไฟล์ใน ZIP, ชื่อซ้ำหลัง sanitize, CRC/การแตกไฟล์ และแนบ manifest ที่บอก hook, secondary, model, source frame และ dimensions

แก้ข้อบกพร่องที่พบแล้วดู preview ใหม่เฉพาะหน้าที่แก้ ไม่เพิ่มขั้นตอนตรวจที่ไม่เกี่ยวกับงาน

## ส่งมอบ

ส่ง preview และลิงก์แก้ไข Canva พร้อมข้อความสั้น ๆ: hook ที่เลือก, ขนาด/ประเภท, หน้าต้นแบบ และสถานะบันทึก หากเครื่องมือกำหนดให้อนุมัติก่อน commit ให้เตรียมงานและตรวจให้ครบก่อนแสดง preview ขออนุมัติขั้นสุดท้าย โดยอธิบายว่าข้อกำหนดมาจากเครื่องมือใด

ส่ง PNG/JPG เพิ่มเฉพาะเมื่อผู้ใช้ขอและ export ได้จริง ภาพ thumbnail จาก API เป็น preview ไม่ใช่ไฟล์ส่งออกคุณภาพเต็ม
เมื่อส่งไฟล์ภาพหลายใบ ให้ตั้งชื่อไฟล์ตามชื่อ Timeline ต้นทาง ใช้การสะกดเดิม และเปลี่ยนเฉพาะอักขระที่ระบบไฟล์ใช้ไม่ได้
