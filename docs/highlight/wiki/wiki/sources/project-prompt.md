# Prompt คัดไฮไลต์และสร้าง Resolve Timeline

อ่านเอกสารครบและเก็บสำเนาตรงต้นฉบับไว้ ณ วันที่นำเข้า เอกสารนี้กำหนด workflow ไม่ใช่หลักฐานว่าขั้นตอนดังกล่าวรันสำเร็จแล้ว

## ตัวแปรและผลลัพธ์

สำเนานี้ระบุภาษาไทย หมวด `gameplay`, `fun`, `meme` ความยาว 30–180 วินาที อัตราส่วน 16:9 และ `APPROVAL=auto` ค่าเหล่านี้เป็นสถานะ ณ วันที่บันทึก ต้องอ่าน `prompt.md` ที่ใช้งานจริงใหม่ทุกงาน ไม่ใช้สำเนาวิกิเป็นค่าปัจจุบัน ([ต้นฉบับ](../../raw/2026-10-04-project-prompt.md), “ตัวแปรของงานนี้” และ “หลักการ: ห้ามฝังข้อมูลไว้ตายตัว”)

สิ่งส่งมอบกำหนด inventory, candidate list พร้อมเวลา/หมวด/เหตุผล, Timeline หนึ่งรายการต่อคลิป และหลักฐานการตรวจช่องว่าง/ซ้อนและความยาวเฟรม ([ต้นฉบับ](../../raw/2026-10-04-project-prompt.md), “สิ่งที่ต้องส่งมอบ”)

## การหาและตรวจช่วง

ขั้นตอนที่ระบุคือคัดช่วงจากเสียง ถอดเสียงเฉพาะช่วงพร้อมบริบทรอบข้าง ทำภาพตัวอย่าง และพิจารณาจุดเริ่ม/จบ ความดังเป็นวิธีหาผู้สมัคร ไม่ใช่หลักฐานความสนุก เอกสารเองระบุความเสี่ยงว่าจะพลาดมุกเสียงเรียบ ([ต้นฉบับ](../../raw/2026-10-04-project-prompt.md), “วิธีวิเคราะห์” และ “ความเสี่ยง”)

ต้นฉบับฟุตเทจอ่านอย่างเดียว ผลงานเก็บที่ `WORK_DIR` ค่า fps และสถานะ Resolve ต้องตรวจสด ห้ามนำข้อมูลเก่ามาแทนสถานะจริง งาน rough-cut เป็น assembly และไม่เพิ่มกราฟิกหรือเอฟเฟกต์โดยไม่มีคำสั่ง ([ต้นฉบับ](../../raw/2026-10-04-project-prompt.md), “หลักการ: ห้ามฝังข้อมูลไว้ตายตัว”, “Resolve” และ “ข้อกำหนดที่ห้ามละเมิด”)

## ความขัดแย้งภายในเอกสาร

ตารางกำหนด `APPROVAL=auto` แต่หัวข้อความเสี่ยงยังกล่าวถึงจุดอนุมัติ `APPROVAL=ask` บันทึกความต่างนี้ไว้ ขั้น “วิธีเริ่ม” รองรับทั้งสองค่า และข้อความกำหนดให้คำสั่งผู้ใช้ปัจจุบันชนะ จึงไม่ควรเพิ่มจุดรอเพียงเพราะประโยคในส่วนความเสี่ยง ([ต้นฉบับ](../../raw/2026-10-04-project-prompt.md), “ตัวแปรของงานนี้”, “ความเสี่ยง” และ “วิธีเริ่ม”)

ชื่อ tool/skill ในเอกสารอาจเป็นของอีก runtime ต้องตรวจเครื่องมือที่มีจริงก่อนใช้ การนำเข้าครั้งนี้ไม่ได้ตรวจแผน Hermes หรือพิสูจน์ว่าเครื่องมือทั้งหมดพร้อมใช้ ([ต้นฉบับ](../../raw/2026-10-04-project-prompt.md), “Skills ที่ต้องโหลดก่อนเริ่ม” และ “แผนที่ใช้”)
