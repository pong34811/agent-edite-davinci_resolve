# วิกิช่วย skill คัดคลิปอย่างไร

## คำตอบ

วิกิเป็นความจำที่เก็บเป้าหมาย รสนิยม เหตุผลคัดคลิป และ feedback ข้ามงาน ส่วน skill ให้ขั้นตอนลงมือทำ การแบ่งหน้าที่นี้เป็นข้อเสนอการใช้งานตาม [brief](../../raw/2026-10-04-user-project-brief.md), “ต้นฉบับ” และ workflow ที่มีใน [prompt](../../raw/2026-10-04-project-prompt.md), “วิธีวิเคราะห์”

## จุดที่ใช้ร่วมกัน

| ขั้น | วิกิส่งความรู้อะไรให้ | งานของ skill/tool จริง |
| --- | --- | --- |
| เริ่มงาน | เป้าหมายและสิ่งที่เคยเรียนรู้ | อ่าน input/job สด ทำ inventory |
| หา candidate | หมวด เกณฑ์ทดลอง และจุดที่วิธีคัดเดิมอาจพลาด | วิเคราะห์เสียง ถอดเสียง อ่าน transcript ตรวจภาพ/ช่วงจริง |
| เลือกคลิป | เหตุผลเลือก/ปฏิเสธเดิมพร้อมบริบท | ระบุ in/out และหลักฐานของงานนี้ |
| rough-cut | ขอบเขต house-style ที่ยืนยัน | ใช้ Resolve workflow และตรวจผลจริง |
| รับ feedback | บันทึกเหตุผลและแยก preference จากเหตุการณ์เฉพาะ | แก้คลิปและอัปเดต house-style ตาม protocol |
| หลังเผยแพร่ | เปรียบเทียบเกณฑ์กับผลจริงเมื่อมีข้อมูล | รับ analytics ที่ผู้ใช้ให้หรืออนุญาตให้อ่าน |

แถว input/วิเคราะห์/Resolve อิง [prompt](../../raw/2026-10-04-project-prompt.md), “หลักการ: ห้ามฝังข้อมูลไว้ตายตัว”, “วิธีวิเคราะห์”, “สิ่งที่ต้องส่งมอบ”; แถว preference อิง [house-style](../../raw/2026-10-04-house-style.md), “Capture protocol” และ “Rejected by default”; แถว analytics เป็นข้อเสนอ ยังไม่มีข้อมูลผลเผยแพร่

## วิธีเชื่อมที่เพิ่มไว้

ไฟล์ [AGENTS.md ของโปรเจกต์](../../../../../AGENTS.md) ให้เอเจนต์อ่านสารบัญ ภาพรวม และหน้าคัดคลิปก่อนงานเลือก/ตัดคลิป เอเจนต์ต้องเปิด actual skill เช่น `house-style`, `subtitle-analyzer` หรือ `davinci-resolve-workflow` ตามงาน ไม่ถือว่าสรุปในวิกิแทน skill ได้ การเพิ่มเอกสารนี้ไม่ได้ติดตั้งหรือเรียกใช้ skill เหล่านั้น

เมื่ออยู่ใน runtime ที่ไม่อ่าน AGENTS.md อัตโนมัติ ให้เพิ่มคำสั่งเริ่มงาน:

> อ่าน llm_wiki/AGENTS.md และ llm_wiki/wiki/index.md ใช้ความรู้เกี่ยวกับการคัดคลิป Vtuber ไทยร่วมกับ skill ที่มีจริง อ่าน prompt.md และ house-style ปัจจุบันก่อนทำงาน ใช้ฟุตเทจและค่าของงานล่าสุด แล้วบันทึก feedback ที่ใช้ซ้ำได้กลับวิกิ

## สิ่งที่ต้องตรวจสด

path วิดีโอ inventory, fps, สถานะ Resolve, จำนวนคลิป, aspect และ approval เป็นค่าของงาน ไม่ใช่ความจำถาวรของวิกิ ตัวแปรปัจจุบันต้องตรวจจาก live prompt และระบบจริง ([prompt](../../raw/2026-10-04-project-prompt.md), “ตัวแปรของงานนี้”, “หลักการ: ห้ามฝังข้อมูลไว้ตายตัว”, “Resolve”)

มีความต่างภายใน snapshot เรื่อง auto/ask ดู [หน้าสรุป prompt](../sources/project-prompt.md) ไม่บังคับหยุดจากบันทึกเก่าเมื่อผู้ใช้อนุมัติไว้แล้ว

## สถานะปัจจุบัน

อัปเดต 2026-10-04: pipeline ถูกรันจริงหนึ่งงานแล้ว ([บันทึกรอบงาน](hoshi-2026-10-03-run.md)) และมี skill ชื่อ `long-video-highlight-clipping` กับ `livestream-highlight-clipping` ในโฟลเดอร์ skill ของ Hermes (นอก repo นี้; เอเจนต์เห็นและอ่านในรอบนั้น) ที่ระบุข้อควรระวังจากงานจริง เช่น ตัวแปรงานต้องอยู่ในตารางเดียวของ `prompt.md`, ถอดเสียงเฉพาะช่วงที่คัด, การติดตั้ง CUDA DLL บน Windows และการยืนยันผล subagent ด้วย schema test วิกิไม่แทน skill เหล่านั้น ต้องเปิด skill จริงทุกงาน ส่วนโค้ดของ pipeline อยู่ใน `work/` ของ repo (ดู [AGENTS.md](../../../../../AGENTS.md))

สถานะเดิม (2026-10-04, ก่อนรันงานจริง): เพิ่มทางเชื่อมเชิงเอกสารและหน้าความรู้แล้ว ยังไม่ได้เปลี่ยน skill เดิม รันคัดคลิป สร้าง Timeline หรืออัปโหลดจากงานวิกิครั้งนั้น ยังไม่มีหลักฐานว่าการเพิ่มวิกิทำให้ผลคัดคลิปดีขึ้น ต้องประเมินจากงานจริง
